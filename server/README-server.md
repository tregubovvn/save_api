# Настройка сервера публикации — tregubovvn.ru

Инструкция, как подготовить ваш сервер к публикации заданий из File API.
После настройки файлы будут появляться в папке `Task_Arhive` и будут
доступны по прямым ссылкам вида:

```
https://tregubovvn.ru/Task_Arhive/ReadTest_8241937605.xml
```

Схема — **HTTPS**: SSL-сертификат уже подключён, пароль публикации и XML
передаются по зашифрованному соединению.

---

## Что понадобится

- Хостинг сайта **tregubovvn.ru** с **PHP 7.4 или новее** (обычный shared-хостинг подходит).
- Доступ к файловому менеджеру хостинга или FTP/SFTP.
- **HTTPS** на сайте (вы уже подключили; бесплатный сертификат Let's Encrypt
  продлевается автоматически — раз в год проверяйте, что он не истёк).
- Сайт должен открываться по `https://tregubovvn.ru` **без ошибок сертификата**
  (см. Шаг 4 — как проверить).

---

## Шаг 1. Загрузите publish.php на сервер

1. Откройте файловый менеджер хостинга (или подключитесь по FTP).
2. Загрузите файл **`publish.php`** в **корень сайта** — туда, где лежит
   главная страница `index.html`/`index.php` домена `tregubovvn.ru`.

   После загрузки эндпоинт будет доступен по адресу
   `https://tregubovvn.ru/publish.php`.

   > Загрузить в подпапку тоже можно (например, `/api/publish.php`) — тогда
   > папка архива создастся рядом со скриптом (`/api/Task_Arhive`), и адрес
   > эндпоинта нужно будет указать в настройках тестовой страницы.

## Шаг 2. Задайте пароль публикации

Откройте `publish.php` в редакторе файлового менеджера и в начале файла
замените пароль на свой:

```php
const SERVER_PASSWORD = 'CHANGE_ME_PASSWORD';   // ← ваш пароль
```

Правила хорошего тона: не короче 12 символов, без словарных слов.
Этот же пароль потом вводится на тестовой странице
(⚙ Настройки → «Пароль публикации») или задаётся в коде вызовом
`api.setToken('server', '…')`.

Заодно проверьте константу адреса сайта (протокол должен быть `https://`):

```php
const PUBLIC_BASE_URL = 'https://tregubovvn.ru';
```

## Шаг 3. Папка Task_Arhive

Создавать её **не обязательно** — при первой публикации скрипт создаст папку сам.
Если хотите создать вручную:

1. Создайте папку **`Task_Arhive`** в корне сайта (рядом с `publish.php`).
2. Установите права **755** (владелец — запись; остальные — чтение).
   Если публикация ответит ошибкой «нет прав на запись» — попробуйте **775**,
   в крайнем случае **777** (на shared-хостингах PHP обычно работает от вашего
   пользователя, и 755 достаточно).
3. Загрузите в эту папку файл **`htaccess.txt`** (из папки `server/`) и
   переименуйте его на сервере в **`.htaccess`**. Он запрещает просмотр списка
   файлов в папке — останутся только прямые ссылки на конкретные файлы.

## Шаг 4. Проверьте HTTPS

Откройте в браузере адрес

```
https://tregubovvn.ru/publish.php
```

- Сайт открывается по HTTPS **без предупреждений браузера**, и на экране JSON
  вида `{"ok":false,"message":"Пустой запрос…"}` — **всё в порядке**
  (GET-запросы скрипт не обслуживает, это нормальный ответ).
- Браузер показывает предупреждение «не защищено» / «неверный сертификат» —
  сертификат не действует для домена: перевыпустите Let's Encrypt в панели
  хостинга и убедитесь, что он выдан именно для `tregubovvn.ru` (а также
  `www.tregubovvn.ru`, если вы используете поддомен www).
- Самоподписанный сертификат для публикации не годится: браузер отклонит
  запрос, пока пользователь вручную не доверяет сертификату — включите
  Let's Encrypt или купленный сертификат.

Автоматический редирект `http://` → `https://`, если он включён на хостинге,
мешать не будет: библиотека сразу обращается по `https://`.

## Шаг 5. Проверка публикации

### Вариант А — через тестовую страницу

1. Откройте тестовую страницу `index.html` (из этой поставки) по
   `https://`, `http://`, `localhost` или прямо с диска (`file://`) —
   сервер работает по HTTPS, mixed content не возникнет.
2. ⚙ Настройки → заполните:
   - «Пароль публикации» — тот же пароль, что в `SERVER_PASSWORD`;
   - «Адрес эндпоинта» — `https://tregubovvn.ru/publish.php`;
   - «Папка архива» — `Task_Arhive`.
3. Выберите тип задания (ReadTest / MoodleTest / FormulaTest) и нажмите
   **🚀 На сервер**.
4. В журнале появится имя файла вида `ReadTest_8241937605.xml` и ссылка.
5. Откройте ссылку `https://tregubovvn.ru/Task_Arhive/<имя файла>` — должен
   открыться XML. Кнопка «📄 Файлы на сервере» покажет список опубликованного.

### Вариант Б — curl (проверка без браузера)

```bash
curl -X POST https://tregubovvn.ru/publish.php \
  -H "Content-Type: application/json" \
  -d '{"action":"publish","password":"ВАШ_ПАРОЛЬ","folder":"Task_Arhive","fileName":"ReadTest_1234567890.xml","content":"<?xml version=\"1.0\" encoding=\"UTF-8\"?><quiz><question type=\"description\"><questiontext><text>Проверка</text></questiontext></question></quiz>"}'
```

Ожидаемый ответ:

```json
{"ok":true,"message":"Файл опубликован","fileName":"ReadTest_1234567890.xml","size":…,"url":"https://tregubovvn.ru/Task_Arhive/ReadTest_1234567890.xml","updated":false}
```

Список файлов:

```bash
curl -X POST https://tregubovvn.ru/publish.php \
  -H "Content-Type: application/json" \
  -d '{"action":"list","password":"ВАШ_ПАРОЛЬ","folder":"Task_Arhive"}'
```

Неверный пароль → HTTP 401 `{"ok":false,"message":"Неверный пароль публикации"}`.

## Как это работает (протокол)

Библиотека отправляет на эндпоинт **POST** с JSON-телом:

| Поле | Действие `publish` | Действие `list` |
|---|---|---|
| `action` | `"publish"` | `"list"` |
| `password` | пароль публикации | пароль публикации |
| `folder` | `Task_Arhive` | `Task_Arhive` |
| `fileName` | `ReadTest_1234567890.xml` | — |
| `content` | текст XML | — |

Ответ — всегда JSON `{ok, message, …}`; при ошибке — соответствующий HTTP-код
(401 неверный пароль, 400 неверное имя/пустое тело, 413 слишком большой файл,
405 метод не POST, 500 проблемы с правами).

Имя файла формирует библиотека: `Тип` + `_` + случайное 10-значное число + `.xml`.
Тип — один из `ReadTest`, `MoodleTest`, `FormulaTest` (список настраивается
и в API — `taskTypes`, и на сервере — `ALLOWED_TASK_TYPES`).

## Безопасность: что уже сделано и что можно усилить

Сделано в `publish.php`:

- **Пароль** на публикацию и просмотр списка; сравнение через `hash_equals`
  (защита от timing-атак) + пауза 0,3 с при неверном пароле (замедляет перебор).
- **Строгий шаблон имени файла** — на сервер попадут только файлы
  `Тип_10цифр.xml`; исключены path traversal и загрузка `.php`.
- **Лимит размера** (512 КБ) и проверка, что содержимое похоже на XML.
- В папке архива **`.htaccess`**: запрет листинга и запрет исполнения PHP.
- **HTTPS**: пароль и содержимое файлов передаются по зашифрованному каналу.

Рекомендации по желанию:

- Ограничьте CORS своим приложением: замените `Access-Control-Allow-Origin: *`
  в `publish.php` на конкретный origin, например
  `header('Access-Control-Allow-Origin: https://tregubovvn.github.io');`
  (один origin на строку; для нескольких — определяйте origin из `$_SERVER['HTTP_ORIGIN']`).
- Периодически меняйте пароль (правится в одной строке `SERVER_PASSWORD`).
- Если хостинг позволяет — настройте автоматическое резервное копирование
  папки `Task_Arhive`.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `Failed to fetch` в браузере | Неверный адрес эндпоинта, истёкший/неверный сертификат или сервер недоступен. Откройте `https://tregubovvn.ru/publish.php` напрямую — должен вернуться JSON без предупреждений браузера. |
| Предупреждение браузера о сертификате | Сертификат не выдан для `tregubovvn.ru` или истёк — перевыпустите Let's Encrypt в панели хостинга. Самоподписанный сертификат браузер не примет. |
| Ошибка CORS в консоли браузера | Эндпоинт не отвечает с CORS-заголовками: проверьте, что запрос идёт именно к `publish.php`, а не на редирект (например, на `http://`-версию — указывайте адрес сразу с `https://`). |
| HTTP 401 «Неверный пароль» | Пароль в ⚙ Настройки отличается от `SERVER_PASSWORD` в `publish.php`. |
| HTTP 500 «Нет прав на запись» | Права папки `Task_Arhive`: поставьте 775 (или 777) через файловый менеджер. |
| HTTP 500 «Не удалось создать папку» | Создайте `Task_Arhive` вручную в корне сайта, права 755+. |
| HTTP 413 | Файл больше 512 КБ — увеличьте `MAX_CONTENT_SIZE` в `publish.php`. |
| «Имя файла должно быть вида …» | Имя не совпало с шаблоном `Тип_10цифр.xml` — на сервере включён строгий контроль; имя должно содержать тип ReadTest/MoodleTest/FormulaTest и ровно 10 цифр. |
| Страница видит 404 | `publish.php` лежит не в корне — поправьте «Адрес эндпоинта» в ⚙ Настройках или перенесите файл. |

## Интеграция в сторонние приложения

Другие приложения могут публиковать задания напрямую, без тестовой страницы:

```html
<script src="file-api.js"></script>
<script>
    const api = FilesApi.create({
        serverEndpoint: 'https://tregubovvn.ru/publish.php',
        serverFolder: 'Task_Arhive',
        serverBaseUrl: 'https://tregubovvn.ru',
    });
    api.setToken('server', 'ВАШ_ПАРОЛЬ');          // пароль публикации
    api.setContent(xmlText);                        // XML задания

    const r = await api.publishToServer({ taskType: 'MoodleTest' });
    // r.fileName — «MoodleTest_8241937605.xml»
    // r.rawUrl   — «https://tregubovvn.ru/Task_Arhive/MoodleTest_8241937605.xml»
    // r.taskUrl  — готовая ссылка на тест в приложении mt_v2
</script>
```

Тот же протокол легко повторить на любом другом языке (Python, C#, 1С…):
POST JSON на `publish.php` с полями `action`, `password`, `fileName`, `content`.
